# FeltKit capability audit: auth/identity/authority and agent primitives

Date: 2026-11-05. Read-only audit. No repository files were modified.

## 0. Method and provenance (read first)

- **Working tree changed during the audit.** At the start `/home/user/feltkit` had `claude/scoped-events` (af5b290) checked out. A few calls later the same checkout was on `main` (f49d9ac). I did not switch it, so something else did. To keep the evidence stable I exported both refs with `git archive` (a read-only operation) to:
  - `fk-branch` = `claude/scoped-events` @ af5b290 → a read-only export of that commit
  - `fk-main` = `main` @ f49d9ac → a read-only export of that commit
  All `file:line` citations below are paths inside the repo (`packages/sdk/...`) at **af5b290**. Line numbers on main are the same unless a row says otherwise.
- **Branch-only content** (`diff -rq` of the two exports): `src/runtime/events.ts` and `src/event-stage.ts` are new. `app.event` and `ctx.events` are added to `app.ts`, `context.ts`, `runtime.ts`, `client/index.ts` and `react/index.tsx` (`useEvent`). `authorize.ts` adds `kind: "observe"` and lets a hook *return* a decision with `code: "NOT_FOUND"`. The branch also adds `test/events.test.ts`, `test/client-reconnect.test.ts`, the events fixtures, and AppBoundry guest/host event support. Every other file in this audit is identical on `main`.
- **Tests were run, not just read.** I symlinked the repo's `node_modules` into the branch export (and removed the symlinks afterwards) and ran `node --import tsx --test`:
  - accounts, account-email, sign-in-providers, auth, authorize, events: 20 tests in the first run, all `ok` (output cut off at 20 lines).
  - sign-in-providers, authorize, events, decisions, approval-required, agent, agent-lifecycle, cli, crypto-token: 67/67 pass.
  - console, testing, resolver-model, cli-defects: 21/21 pass.
  Multiplayer's tests were **not** run.
- Status scale: 1 = implemented and tested, 2 = implemented but incomplete, 3 = contract/schema only, 4 = planned/documented only, 5 = missing.
- **Fact** means I confirmed it in source or by a test run. **Inference** is labeled as such.

## C. DSL / config language

- **FeltKit has no DSL or parser.** Configuration is TypeScript only (`feltkit({...})`, `app.collection/query/mutation/event`). `git grep` on af5b290 for `use auth`, grammar, lexer, peggy, chevrotain, `.flow` and `parseFlow` finds no parser and no `.flow` files. The only "grammar" hits are AppPort capability-name rules (`src/app.ts:492,668`).
- `docs/PRODUCT-AND-ARCHITECTURE-REVIEW.md:65-70,367-381` says: "`.flow` is not used by FeltKit… Never reads or writes `.flow`".
- **The parser that does exist is FeltDB's**, a dependency: `node_modules/@feltdb/core/dist/flowspec.d.ts` (v0.21.0) exports `parseFlowSpec`, `validateFlowSpec`, `formatFlowSpec`, `diffFlowSpec`, `flowSpecToManifest` and `manifestToFlowSpec`. `FlowSpec` has collections, workflows, triggers and `agents: FlowBlock[]`, with **no auth/roles/tenancy constructs** (from grep of the `.d.ts`). FeltKit does not import it.

## E. Gaps relevant to the requested themes

- **Tenancy (5).** There is no tenant, org, membership, invitation, tenant switching or tenant-scoped session. The AppPort Services tenant is fixed to the app name, and Files are shared app-wide. What exists is the `authorize` hook (1, read-fenced and live-revoking), `ctx.crypto.token` (1), and scoped `app.event` (1, branch only). Multiplayer has rebuilt tenancy itself in roughly 300+ lines.
- **Typed claims (5).** The principal is `{id, type, displayName, roles}` with string roles and permissions. There are no custom claims, no tenant or org claim, and no generated types from `roles`. The `authenticate` hook cannot pass attributes. Roles are snapshotted into sessions, and accounts have no role-change path.
- **Magic link / OTP (5).** The parts exist (signed account links in `account-links.ts`, Mailerport, the send budget, `ctx.crypto.token`), but there is no `"signin"` link purpose, route or client method. A related gap is account lifecycle (profile, e-mail change, delete, disable): all 5.
- **Agent principals and delegation (agent type 2, delegation 4).** `type:"agent"` exists, and agents cannot approve or run `approval:"required"` mutations directly. There is no on-behalf-of chain, scope narrowing, delegation expiry or revocation, and no agent lifecycle. Delegation is planned through AuthBoundry (`docs/AGENT-OPERATIONS.md` §2 and PR 4); `delegatedBy` is always null. Studio's coding agent is a shared id `coding-agent` that copies a person's roles. API keys all share one role set.
- **Specialized agent definitions (5).** There is one built-in agent (`feltkit` v1), a closed playbook list, and models used only as a chooser among options (no generation or tool loop). There is no app-declared agent with its own tools, model, goals or version. There is no event-triggered hosted execution (FK-GAP-008) and no evaluation harness. Multiplayer works around all of this with an external worker process and its own queue.
